# Grok adapter

Target: Grok and Grok-connected coding or research workflows.

Start from `AGENTS.md`, then use `README.md`, `docs/02-methodology.md`, `docs/13-blueprint-compiler.md`, `docs/14-vertical-blueprint-contracts.md`, `docs/15-model-execution-principles.md`, `blueprints/`, and `scorecards/` as source of truth.

Official pipeline:

Raw request -> Intake -> Specification -> Project Profile Selection -> Vertical Blueprint -> Plan -> Tasks -> Implementation -> Evaluation Scorecard -> Release/Iteration

Grok must separate research, assumption, and implementation. Do not cite live or external facts without verification. Do not convert ambiguous product requests into generic apps.

For incomplete requests, ask at most 5 blocking questions, then proceed only with explicit reversible assumptions and quality gates.

When used for implementation, report changed files, validation, open risks, and scorecard.
